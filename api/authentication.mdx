Every protected endpoint in the Toban API uses the `get_current_user` FastAPI dependency defined in `app/core/auth.py`. This dependency reads the `Authorization: Bearer` header from the incoming request, decodes the Supabase-issued JWT using `SUPABASE_JWT_SECRET`, and returns a user context dictionary that route handlers receive as an injected argument. No session store or database lookup is required for basic authentication — all necessary identity information is encoded directly in the token.

## Obtaining a Token

Toban authenticates users through [Supabase Auth](https://supabase.com/docs/guides/auth), which supports email/password, GitHub OAuth, and Google OAuth out of the box. After a successful sign-in, Supabase returns a session object containing an `access_token`. This token is the JWT you pass to the API.

<Tip>
  When using the Supabase JavaScript client, retrieve the current session token with:

  ```javascript
  const { data: { session } } = await supabase.auth.getSession()
  const jwt = session.access_token
  ```

  The frontend stores this token and attaches it automatically to every API request via an `Authorization` header.
</Tip>

The token has a limited lifetime (typically one hour). Supabase JS automatically refreshes the session in the background; your frontend should always read the token freshly from `getSession()` rather than caching it long-term.

## Making Authenticated Requests

Pass the JWT as a Bearer token in the `Authorization` header on every request to a protected endpoint. Below is a minimal `curl` example:

```bash
curl -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  http://localhost:8000/api/v1/teams/
```

In a JavaScript fetch call:

```javascript
const response = await fetch('http://localhost:8000/api/v1/teams/', {
  headers: {
    'Authorization': `Bearer ${session.access_token}`,
    'Content-Type': 'application/json',
  },
})
```

The `Content-Type: application/json` header is required for `POST`, `PUT`, and `PATCH` requests that send a body. It is optional for `GET` and `DELETE`.

## Token Validation

The backend validates every token using the `decode_token` function in `app/core/auth.py`. Validation uses the **HS256** algorithm with `SUPABASE_JWT_SECRET` as the signing key. The function attempts three progressive verification strategies to maximise Supabase compatibility:

1. **Signature only** — verifies the signature while skipping audience and issuer checks.
2. **Signature + audience** — additionally verifies the `aud` claim against the Supabase project URL and its `/auth/v1` sub-path.
3. **Signature + audience + issuer** — full verification including the `iss` claim.

The first strategy that succeeds returns the decoded payload. If all three fail, a `401 Unauthorized` response is returned immediately.

<Warning>
  The `SUPABASE_JWT_SECRET` environment variable on the backend **must match** the JWT secret shown in your Supabase project under **Project Settings → API → JWT Settings**. A mismatch causes every token to fail signature verification with `401 Unauthorized`, even when the token itself is valid.
</Warning>

## User Context from Token

After successful validation, `get_current_user` extracts user identity and optional team context from the decoded JWT payload and returns them as a plain Python dictionary:

| Field | Source claim | Description |
|---|---|---|
| `id` | `sub` | User UUID — used for all team access checks |
| `email` | `email` | User email address |
| `role` | `role` | Supabase auth role (default: `"authenticated"`) |
| `current_team_id` | `current_team_id` | Active team UUID (if embedded in token) |
| `current_team_role` | `current_team_role` | Role within the active team (if embedded) |
| `teams` | `teams` | List of team membership objects (if embedded) |

Route handlers receive this dictionary via FastAPI's dependency injection:

```python
from fastapi import Depends
from app.core.auth import get_current_user

@router.get("/me")
async def get_me(current_user: dict = Depends(get_current_user)):
    return {"user_id": current_user["id"], "email": current_user["email"]}
```

## Auth Flow — Source Code

The following is the complete `get_current_user` dependency and its supporting `decode_token` function, taken directly from `app/core/auth.py`:

```python
import logging
import time
from typing import Dict

from fastapi import Depends, HTTPException, status
from fastapi.security import HTTPAuthorizationCredentials, HTTPBearer
from jose import jwt

from app.config import settings

security = HTTPBearer()


def decode_token(token: str) -> Dict:
    """
    Decode and validate a JWT token from Supabase Auth.
    Attempts three progressive verification strategies for compatibility.
    """
    logger = logging.getLogger(__name__)

    try:
        jwt_secret = settings.SUPABASE_JWT_SECRET
        if not jwt_secret:
            raise ValueError("JWT secret is not configured")

        supabase_url = settings.SUPABASE_URL.rstrip("/")
        audiences = [supabase_url, f"{supabase_url}/auth/v1"]

        # Strategy 1: signature-only verification
        try:
            return jwt.decode(
                token,
                jwt_secret,
                algorithms=["HS256"],
                options={"verify_signature": True, "verify_aud": False, "verify_iss": False},
            )
        except Exception:
            pass

        # Strategy 2: signature + audience
        try:
            return jwt.decode(
                token,
                jwt_secret,
                algorithms=["HS256"],
                audience=audiences,
                options={"verify_signature": True, "verify_aud": True, "verify_iss": False},
            )
        except Exception:
            pass

        # Strategy 3: full verification
        return jwt.decode(
            token,
            jwt_secret,
            algorithms=["HS256"],
            audience=audiences,
            issuer=supabase_url,
            options={"verify_signature": True, "verify_aud": True, "verify_iss": True},
        )

    except HTTPException:
        raise
    except Exception as e:
        logger.error(f"Token verification failed: {str(e)}")
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid authentication credentials",
            headers={"WWW-Authenticate": "Bearer"},
        )


def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(security),
) -> Dict:
    """
    Extract and return the authenticated user from the JWT token.
    Raises 401 if credentials are missing or invalid.
    """
    if not credentials:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="No authentication credentials provided",
            headers={"WWW-Authenticate": "Bearer"},
        )

    payload = decode_token(credentials.credentials)

    # Validate expiration manually as a safety net
    if payload.get("exp") and time.time() > payload["exp"]:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Token has expired",
            headers={"WWW-Authenticate": "Bearer"},
        )

    user_id = payload.get("sub")
    if not user_id:
        raise HTTPException(
            status_code=status.HTTP_401_UNAUTHORIZED,
            detail="Invalid token payload",
            headers={"WWW-Authenticate": "Bearer"},
        )

    user_data = {
        "id": user_id,
        "email": payload.get("email", ""),
        "role": payload.get("role", "authenticated"),
    }

    # Include team context if embedded in the token
    if payload.get("current_team_id"):
        user_data["current_team_id"] = payload.get("current_team_id")
        user_data["current_team_role"] = payload.get("current_team_role")

    if payload.get("teams"):
        user_data["teams"] = payload.get("teams")

    return user_data
```

## Error Responses

| Scenario | HTTP Status | `detail` message |
|---|---|---|
| `Authorization` header missing entirely | `401 Unauthorized` | `"No authentication credentials provided"` |
| Token signature invalid or secret mismatch | `401 Unauthorized` | `"Invalid authentication credentials"` |
| Token has passed its `exp` timestamp | `401 Unauthorized` | `"Token has expired"` |
| `sub` claim absent from payload | `401 Unauthorized` | `"Invalid token payload"` |
| User authenticated but lacks team membership | `403 Forbidden` | `"You don't have access to this team"` |
| User authenticated but role is insufficient | `403 Forbidden` | `"Insufficient permissions for this action"` |

All `401` responses include a `WWW-Authenticate: Bearer` response header as required by RFC 6750.
